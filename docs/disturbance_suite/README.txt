DISTURBANCE-AWARE MONITORING: CHECKPOINT BEFORE SENSING REVISION

This checkpoint records ten paired 300 s nonlinear quadrotor simulations, seed 9101. The original sensing cone has a 45 degree half-angle: radius = altitude, approximately 3.2 m. Both planners use this same sensing model and the same physical execution filter.

View output/disturbance_suite/final_report through an HTTP server. Its results.json contains exact configuration, measurement protocol, source hashes, audit outcomes, development selection and limitations. Playback data are archived as compressed JSON. Full 100 Hz execution/search logs and historical development cohorts remain in local output/disturbance_suite (several GB); they are deliberately not added to Git. Source snapshots and raw-run paths are listed in the report.

Run fresh paired simulations using scripts/run_disturbance_suite.py. Final configuration: --seconds 300 --seed 9101 --horizon 12 --dt .2 --iterations 3 --modes 13 --proposals 26 --worlds 2 --validation-worlds 4 --temperature .06 --prior-std 1.8 --survey-count 64 --inducing-count 64 --short-length .6 --long-length 1.8 --prediction-filter hard --prediction-substeps 2 --validation-batch-size 27 --execution-margin .7 --planning-clearance .6 --sensor-half-angle-degrees 45 --output FRESH_DIRECTORY. For distributed use execution-margin .9 and planning-clearance .9 for both planners. Select cases with --cases.

These are development-selected synthetic fields, one paired seed, with 64 shared noisy pre-mission measurements. No hardware, CFD, held-out robustness or real-time deadline claim. Planning pauses the simulated mission clock.

SENSING-RANGE REVISION
The updated suite runner defaults to a 25 degree half-angle (50 degree full camera field of view), giving a 1.492 m radius at 3.2 m height. The shared Settings class retains 45 degrees as its legacy default so historical scripts/configurations preserve their original model. Both prediction and100 Hz clarity updates use the configured angle. Gaussian sigma 2.2 m, sensor R 0.3 and other experiment settings are unchanged except the common slalom execution-filter update rate described below. Select docs/disturbance_suite/sensor25_cases.json for the new ten-case cohort; final_cases.json identifies the old 45 degree checkpoint. check_sensing_revision.py verifies that angle and explicitly declared common controller-rate adjustments are the only configuration changes and that each initial state, environment and information set are identical. The current final_report is replaced only after new pairs are audited; the old viewer remains under output/disturbance_suite/sensor45_archive.

WIND DISPLAY
Physical wind speed has its own selectable spatial layer and a shared 0–4.2 m/s scale. Colored vectors encode the prescribed true field. Each aircraft readout gives the actual wind norm and x/y components, horizontal ground speed and actual-altitude sensing radius. Posterior mean speed and component standard deviation remain separate layers. These are quantities from recorded simulations, with no visual rescaling of the physical model.

For the narrower rerun, use the checkpoint command above with --sensor-half-angle-degrees 25 and a fresh output directory. Keep the per-case clearance overrides unchanged.

Slalom calibration: the narrower-footprint blind run contacted a building at 88.35 s with the old 20 Hz execution-filter update rate. That recording is preserved under sensor25_complex300/slalom and excluded from successful comparisons. A 0.9 m buffer trial failed for both planners because its initial 1.5 m-wide aisle cannot accommodate that buffer; it is preserved under sensor25_slalom_buffer300. The subsequent rate trial uses --execution-dt .02 (50 Hz) for BOTH planners, with the original execution margin 0.7 m and geometric planning clearance 0.6 m. It changes numerical control sampling without claiming a general controller correction or formal safety guarantee. The selection manifest and revision audit explicitly record the extra setting.
